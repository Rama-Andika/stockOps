# Scan Keyboard

The `hideScanKeyboard` preference (Pengaturan → Cara Input Barang, default OFF) puts `inputMode="none"` on exactly TWO fields: the barcode field and the qty field in `ScanBar`. It asks the browser not to open the SOFT keyboard and nothing more — the fields stay focusable, enabled and writable, so the scanner's wedge keystrokes and the PDT's own keys still arrive. It must never become `readOnly`, `disabled` or a `blur()` on focus: each of those drops every scan without a sound, the same failure shape the focus effect and the scanner wedge in `session-cockpit.tsx` exist to prevent. It is deliberately NOT applied to any field where typing is the job — login, PO search, the picker's search and qty fields, the line editor's qty, invoice and DO number — because hiding the keyboard there leaves no way to enter anything; qty entry on the scan bar goes through the "123" keypad instead. The cockpit reads the preference ONCE per mount (like `manualPick`), so a change made in Pengaturan applies when the operator returns to the session and never mid-scan. The switch lives in the app rather than in Android settings because the Android toggle for the on-screen keyboard was greyed out on the Sunmi PDT this was written for, and a page-level input-mode hint does not depend on it or on which input method is installed. It defaults to OFF so a device updated in the field behaves exactly as before; IT turns it on per device. Locked by `tests/component/scan-controls.test.tsx` (the `ScanBar — keyboard layar` block), `tests/component/session-cockpit-pick.test.tsx` (`kokpit — keyboard layar`) and `tests/component/settings-screen.test.tsx`.
